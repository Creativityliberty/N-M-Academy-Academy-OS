# M13.9 — Course Review & Publish Center + Gemini/Nano Banana Visual System

Release: **v1.2.0**  
Date: **2026-09-01**  
Baseline: **v1.1.9 / M13.8 Tower Chat Rich UX**

## Goal

M13.9 closes the gap between AI course generation and publication. M13.7 can already create a complete draft; M13.9 adds a controlled review surface where a trainer can inspect the generated course, request focused regenerations, compare before/after proposals, accept or reject them, and publish only when the existing Academy domains are ready.

The same milestone also upgrades the existing provider-neutral media layer with Gemini/Nano Banana image generation and a stable Academy Visual Prompt Compiler. No second LMS, pricing engine, page builder, publication path or Tower runtime is introduced.

## Visual provider system

The existing `ImageGenerationProvider → MediaProviderManager → CourseMediaGenerationService` chain remains the integration boundary.

Image providers now include:

```text
ImageGenerationProvider
├── GeminiImageGenerationProvider
├── OpenAiImageGenerationProvider
└── DisabledImageGenerationProvider
```

Gemini defaults to:

```text
gemini-3.1-flash-lite-image
```

The curated Gemini image catalog also exposes:

```text
gemini-3.1-flash-image
gemini-3-pro-image
```

Flash Lite is always coerced to `1K`. Other compatible curated models may use `1K`, `2K` or `4K` according to the runtime image setting.

### Gemini request contract

`GeminiImageGenerationProvider` calls the configured Gemini base URL using the Interactions endpoint and `x-goog-api-key`. The existing provider contract still returns normalized binary image bytes, extension and MIME type to the Academy media service.

Course visual purposes map to stable output shapes:

```text
course_cover      → 16:9
course_thumbnail  → 1:1
```

## Academy Visual Prompt Compiler

All course-image paths use `VisualPromptCompiler` rather than sending a raw title to an image model.

The compiled prompt contains:

```text
COURSE CONTEXT
├── title
├── target audience
├── level
├── language
├── main problem
├── desired transformation
├── main promise
└── unique angle

ACADEMY BRAND
├── academy name
├── theme preset
├── primary
├── secondary
└── accent

VISUAL PURPOSE
├── cover rules
└── thumbnail rules

ART DIRECTION
├── Academy Premium
├── Editorial
├── Cinematic
└── Minimal

OUTPUT RULES
├── safe crop / negative-space rules
├── no fabricated endorsements or logos
├── no watermark imitation
└── no embedded text by default
```

An optional user visual direction can be appended without bypassing the Academy art-direction rules.

## Runtime AI provider settings

A singleton `academy_ai_settings` row stores **non-secret** Academy-wide preferences only:

```text
text_provider
text_model
image_provider
image_model
image_size
image_prompt_preset
respect_branding
avoid_embedded_text
tts_provider
tts_model
```

`AcademyAiSettingsRepository` merges those preferences over the environment/config defaults. If the table is unavailable during boot/migration, the repository falls back to config rather than taking the application down.

API keys are never returned by the Settings UI and are never stored in this table.

New surface:

```text
Settings
└── AI Providers
```

The page shows configured-secret booleans, provider-specific curated model lists and an optional filtered Gemini model discovery action. It never returns an API key value.

## M12 Factory / Coolify provisioning

The Academy Factory can provision an instance with independent text and image providers. For example:

```text
Text     → DeepSeek
Images   → Gemini
Speech   → OpenAI
```

The generated public environment contains model/provider preferences. `GEMINI_API_KEY` joins the existing encrypted deployment-secret payload and is pushed through the existing Coolify secret flow; it is not copied into the public blueprint environment.

## Course Review Center

M13.7 completed One-Brief runs now hand off to:

```text
/trainer/academy-ai/course-creation/{run}/review
```

The trainer reviews real state from the existing domains:

```text
Positioning
Visuals
Curriculum
Lesson content
Narrations
M10 offer
M11 landing
Publish readiness
```

The M13.7 Thinking Orbs and durable course-creation run remain unchanged. M13.8 Mission Tower shell/sidebar/routes/chat are also unchanged.

## Focused regeneration and proposals

M13.9 introduces `course_review_proposals` with explicit `before_payload` and `after_payload` state.

Supported review targets include:

```text
course_positioning
module
lesson
cover
thumbnail
landing
audio
```

The invariant is:

```text
Regenerate
   ↓
Pending proposal
   ↓
Before | After
   ↓
Accept or Reject
```

A proposal does **not** mutate the target while pending.

### Text/content

Focused Academy AI capabilities include:

```text
course.positioning.rewrite
module.rewrite
```

Lesson text continues to reuse the existing `lesson.rewrite` capability, but Review Center acceptance is now responsible for the mutation.

Accepted course/module/lesson content changes dispatch `IndexCourseKnowledge`, preserving M09 Tutor/RAG freshness.

### Media

Cover/thumbnail regeneration produces a candidate file and a `CourseMediaGeneration` trace without immediately swapping the live Course field.

```text
Current cover
     ↓
Generate candidate
     ↓
Before / After
     ↓
Reject → keep current
Accept → swap field + mark generation applied
```

Narration follows the same candidate-first principle for lesson audio.

### Commerce

Offers are displayed from M10 `CourseOffer`. M13.9 does not create a second pricing editor. Commercial mutations remain governed by the existing M10/MCP flows.

### Landing

Landing regeneration reuses the M11 `page.optimize` architecture. The current `AcademyPage` remains the only landing source of truth.

## Publish readiness and publication

Review Center publication is allowed only when the course is structurally ready and no review proposal remains pending.

Current readiness includes:

```text
course belongs to trainer
review/completed One-Brief run
no pending/generating proposal
at least one module
at least one lesson
active default CourseOffer
linked landing, when present, has visible sections
```

Publishing continues through the existing canonical boundary:

```text
Review Center
     ↓
PublishCourseAction
     ↓
Stripe provisioning / course lifecycle
     ↓
linked AcademyPage publish after course success
```

One-Brief-to-Course remains draft-only and does not auto-publish.

## Security and compatibility

- No API credential is persisted in `academy_ai_settings`.
- The Gemini key supplied during design was deliberately not copied into source or release artifacts.
- No new Composer or npm dependency is introduced.
- M10 remains the commerce source of truth.
- M11 remains the landing source of truth.
- M09 remains the course knowledge/RAG system.
- `PublishCourseAction` remains the only publication/Stripe boundary.
- M13.8 Mission Tower code territory remains byte-for-byte unchanged from the v1.1.9 baseline.
