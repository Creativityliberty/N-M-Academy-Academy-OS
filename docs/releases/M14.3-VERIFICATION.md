# M14.3 — Verification Record

**Release:** NÜM Academy OS v1.5.0 — M14.3 Completion Rules + Certificates  
**Date:** 2026-09-02

## Verification policy

The milestone is only considered release-ready after the cumulative available gate passes on source and on a fresh extraction of a control ZIP. The final ZIP is then rebuilt with this record embedded and must pass the same gate again from a second fresh extraction. Dependency-backed checks that cannot run in the local environment remain BLOCKED.

## QA hardening completed before packaging

M14.3 TDD/hostile review caught and fixed:

- completion on an unpublished course;
- instant completion when zero pedagogical criteria are configured;
- `CourseAssignment.is_required_for_completion` missing from canonical `$fillable` fields;
- lesson-scoped required assessments/assignments incorrectly falling through module scope;
- public exposure of the internal certificate revocation reason;
- completion evidence snapshots missing explicit requirement counts;
- historical M14.2 Tower language contract tied to an obsolete English phrase instead of the French-by-default invariant;
- a token-shaped placeholder in Mission Tower setup documentation that caused the release secret scanner to fail.

## Final archive procedure

After this verification record is embedded:

1. rebuild the cumulative v1.5.0 ZIP from the frozen source;
2. generate its SHA-256 sidecar;
3. run `unzip -t` on the exact final archive;
4. extract that exact ZIP into a second new directory;
5. rerun the full available gate;
6. record the final SHA and second-extraction result in the external final verification report delivered with the ZIP.
