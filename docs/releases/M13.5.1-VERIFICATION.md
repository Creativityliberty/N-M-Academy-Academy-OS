## Hardening outcomes

- Tower compilations migration now sorts after Tower missions on fresh installs and remains upgrade-safe when the table already exists.
- Normal Trainer/Admin course deletion archives instead of physically deleting the Course, preserving commerce history.
- Profile deletion is refused when Academy order/refund records require financial retention.
- Draft course creation no longer provisions Stripe; publishing is the single Stripe lifecycle entry point.
- Course publish/unpublish semantics are centralized and always maintain `published_at` consistently.
- Adding a new audio/PDF lesson during course update preserves the uploaded file.
- Changing lesson media type removes stale audio/PDF/video references and storage objects where applicable.
- Academy AI request validation now admits `page.generate`/`page.optimize`, and page optimization requires `page_id`.
- Mission Tower reads the dotted MCP receipt metadata key literally.
- MCP lesson create/update mutations queue `IndexCourseKnowledge` so Tutor/RAG does not remain stale.
- Public Course details no longer borrow mock objectives/prerequisites/reviews/trainer stats from demo course data.
- Public student count now comes from real enrollment counts loaded by the public repository.
