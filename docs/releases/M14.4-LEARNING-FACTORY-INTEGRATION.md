# M14.4 — Learning Experience + Factory Integration

**Release target:** NÜM Academy OS v1.5.1  
**Date:** 2026-09-02

## Purpose

M14.4 closes the integration gap left after M14.1–M14.3. Quiz, Assignments, Completion and Certificates already existed in the master Academy code; this milestone makes them visible, configurable and provisionable as first-class Academy capabilities without introducing a second learning engine.

The rule is now explicit:

> Every major Academy capability added to NÜM Academy OS must be representable by Academy Factory and must be reflected coherently in Student, Trainer and deployment surfaces.

## Student experience

The Student application now exposes `Mes certificats` directly in the Academy sidebar when Certificates are enabled.

The Course Player delegates completion presentation to a focused `CourseCompletionCard` that shows:

- accessible lessons completed / required;
- required assessments passed / required;
- required assignments approved / required;
- remaining requirement categories;
- completed status;
- certificate verification, authenticated PDF download and sharing when the Academy policy allows them.

Certificate actions are not cosmetic. The backend emits them only when the Academy-level certificate policy permits them. Student PDF download is authenticated and ownership-checked. Public verification and public PDF routes are independently protected by the Academy configuration.

When Assessments or Assignments are disabled for an Academy, the Course Player backend no longer serializes those authored primitives to the student payload.

## Trainer experience

Course Studio keeps the existing builder and adds clear governed entry points for:

- `Quiz & évaluations`;
- `Assignments & projets`;
- `Complétion & certificats`.

Each surface follows the Academy feature flags. Trainer routes for Assessment, Assignment, Completion and Certificate operations are also capability-guarded server-side.

## Academy Factory capability model

Factory now separates two concepts that were previously mixed:

```text
Visual template
→ brand / theme / defaults métier

Capability profile
→ product modules enabled in the Academy
```

The first three product profiles are:

```text
essential
creator
pro
```

The capability registry covers:

```text
community
events
ai
tutor
sales
pages
mcp
tower
assessments
assignments
completion
certificates
```

Dependencies are normalized centrally:

```text
certificates requires completion
tower requires mcp
tutor requires ai
```

A template nominates a default capability profile, but the generated Academy blueprint may override that profile and individual capabilities independently.

## Learning & certificate blueprint

Factory can provision these defaults per Academy:

```text
require_all_accessible_lessons
issuer_name
certificate_title
public_verification
pdf_download
student_sharing
```

The resulting Coolify blueprint emits dedicated environment variables for the learning features and certificate policy. Secrets remain outside this configuration model.

## Coolify / deployment

M14.4 keeps the existing one-instance-per-client topology:

```text
App Laravel / React
PostgreSQL 17 + pgvector
Redis
academy-storage
academy-assignments
```

The private assignment mount remains:

```text
academy-assignments:/var/www/html/storage/app/private/assignments
```

The default runtime version is updated to `1.5.1`, and Factory-generated environments now include the M14 learning capability switches and certificate defaults.

## Governance preserved

M14.4 does not introduce direct certificate issuance through Tower/MCP. The existing invariant remains:

```text
certificates.issue  ❌
```

Completion remains calculated by the canonical server-side M14.3 engine, and certificates are issued only from valid completion evidence.

Mission Tower French-by-default behavior and `thinking-orbs@^0.3.1` remain unchanged.

## Compatibility

M14.4 does not replace:

- M14.1 Assessment Engine;
- M14.2 Assignment & Project Engine;
- M14.3 Completion Engine / Certificates;
- M10 CourseOffer commerce;
- M11 Page Builder;
- M09 Tutor/RAG;
- M13 Mission Tower governance.

It integrates those existing primitives into a coherent deployable Academy product surface.
