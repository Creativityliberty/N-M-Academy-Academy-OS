# M13.6 — Canonical Course Domain + AI/Tower CRUD

## Goal

Make Course Studio the canonical creation surface for NÜM Academy OS without rewriting the LMS core. M13.6 extends the real `Course -> Module -> Lesson` domain so a creator or Tower can build a complete course progressively, keep every major part independently editable, and reuse the existing Sales, Page Builder, Tutor/RAG and approval systems.

## Domain changes

### Course

New first-class fields:

- `target_audience`
- `level`: `beginner | intermediate | advanced | all_levels`
- `language`
- `positioning` JSON with `main_problem`, `desired_transformation`, `main_promise`, `unique_angle`
- `thumbnail`

Existing `image` remains the course cover. Existing benefits, objectives, prerequisites and lifecycle fields are retained.

### Module

Adds:

- `description`
- `objectives`

Existing `duration`, `order` and `minimum_access_rank` remain authoritative.

### Lesson

Adds the native `text` lesson type. The existing content/transcript/video/audio/PDF fields remain; no LessonBlock rewrite is introduced.

`audio_url` can coexist with a text/video/PDF lesson as optional narration. Generating narration never converts a text lesson into an audio-only lesson.

## Creator Studio

Course create/edit now serializes the actual lesson `content` and `transcript` fields and exposes positioning, level, language and module access rank.

Course edit adds governed AI media actions:

- Generate course cover
- Generate square thumbnail
- Generate/regenerate narration for an existing lesson

The Student Course Player renders optional narration for text lessons without hiding the lesson text.

## Academy AI

`course.generate` now understands and persists:

- target audience
- level
- language
- positioning

AI-created written lessons use `type=text` instead of pretending to be video lessons.

## Media provider layer

M13.6 introduces provider-neutral contracts:

- `ImageGenerationProvider`
- `SpeechGenerationProvider`

The initial adapters are OpenAI + disabled fallbacks, configured independently from the Academy text provider. This allows, for example, DeepSeek for curriculum generation while using a separate provider for images or TTS.

No new container or datastore is required.

## Academy MCP / Tower CRUD

New/expanded capabilities include:

```text
categories.list
courses.get
courses.create
courses.update
courses.publish
courses.unpublish
courses.archive

modules.list
modules.create
modules.update
modules.delete
modules.reorder

lessons.list
lessons.create
lessons.update
lessons.delete
lessons.reorder

offers.list
offers.update
offers.deactivate

pages.list
pages.create

course.cover.generate
course.thumbnail.generate
lesson.audio.generate
```

`offers.update` is SENSITIVE because it can change or activate live pricing. Offer tools are classified as financial data. Curriculum mutations queue Tutor/RAG re-indexing.

Lesson media normalization keeps `audio_url` available as supplementary narration while preventing incompatible video/PDF references from remaining after a type change.

## Reuse, not duplication

- Commerce continues through M10 `CourseOffer`.
- Public course display prefers active CourseOffer pricing, with legacy `Course.price` only as compatibility fallback.
- Landing pages remain M11 `AcademyPage` / safe Page Builder blocks.
- Tutor knowledge continues through M09 indexing.
- Publish/unpublish/archive continue through the centralized lifecycle actions added in M13.5.1.
- Tower continues to call Academy MCP instead of querying Academy tables directly.

## Deliberately not added

M13.6 does **not** introduce:

- a large LessonBlock subsystem
- quizzes/assignments/certificates/drip as speculative tables
- multi-agent teams
- Dynamic Mission Runtime
- a second commerce engine
- a second page/CMS engine

These remain separate future features only when needed by the course-creation workflow.
