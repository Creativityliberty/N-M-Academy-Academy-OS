## Runtime launcher probe

`./num-academy doctor` correctly reports **Version 1.6.0**, validates generated local APP/DB/Tower credentials and Tower/MCP coherence, then fails truthfully because Docker is unavailable in this runtime. The generated `.env.num-academy` is deleted before packaging and is gitignored by design.

## Security / architecture checks

- Drip does not replace enrollment tier access.
- Tier entitlement and current unlock state are separate concepts.
- Future tier-entitled lessons remain in course progress/completion scope, preventing early 100% or certificate issuance.
- Locked lesson content/media are redacted server-side for enrolled students, including free-preview lessons that are drip-locked after enrollment.
- Tutor/RAG cannot retrieve chunks from currently locked lessons.
- Student MCP lesson/progress tools use the canonical access service.
- Tower uses the same `UnlockRuleDefinitionService` as Course Studio and does not own a parallel rules engine.
- No runtime secret, real `.env`, dependency directory, font binary or symlink is packaged.
