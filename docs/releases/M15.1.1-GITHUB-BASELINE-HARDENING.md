# M15.1.1 — GitHub Baseline Hardening

Version target: **1.6.1**

M15.1.1 is a bounded hardening release over M15.1. It does not introduce a second learning-access engine, change the Mission Tower product model, or alter Factory capability semantics.

## Scope

- align active runtime, env and package version surfaces on 1.6.1;
- keep historical M15.1 documentation historical;
- avoid loading complete enrollment collections only to display a Page Builder student count;
- reuse the shared clipboard hook for Page Builder sharing;
- make runtime launchers derive the version from the local Academy env template;
- keep Linux CI paths case-correct (`tests/Contract`);
- align the application and Coolify production image on Node 24;
- preserve `thinking-orbs@^0.3.1`, Mission Tower French defaults and M15.1 access semantics.

## Page Builder hardening

`PageSectionResolver` now uses `withCount('enrollments')` and reads `enrollments_count` rather than eager-loading every enrollment model simply to display a count.

The Page Builder share control now calls the common `useClipboard` hook. The browser clipboard API remains encapsulated in the shared hook rather than being reimplemented in the renderer.

## Runtime launcher hardening

Both launchers derive the Academy version from `.env.num-academy.example`, with `1.6.1` as a defensive fallback. A generated `.env.num-academy` therefore remains aligned with the checked-in runtime template.

## Node / Coolify hardening

The dependency graph already required Node 24 through active frontend packages. GitHub Actions was using Node 24, while the Alpine package repository used by the Docker build supplied Node 22/npm 10.

That mismatch produced two production-image failures before Vite could build:

1. an engine mismatch for packages requiring Node >=24;
2. npm 10 strict peer resolution around `thinking-orbs@0.3.1 → motion-plus-react → three`.

The production path now uses a canonical `node:24-alpine` stage. The asset/SSR build receives Node/npm from that stage, and the final PHP-FPM image receives the same Node 24 binary for Inertia SSR. We deliberately did **not** downgrade `thinking-orbs` and did **not** add `--legacy-peer-deps` to hide the dependency problem.

## Verification contract

`tests/Contract/M15_1_1GitHubBaselineHardeningContractTest.php` protects:

- v1.6.1 active version surfaces;
- Node >=24 declaration;
- Page Builder SQL enrollment counting;
- shared clipboard usage;
- Node 24 Docker production baseline;
- case-sensitive CI paths;
- PHP 8.4+ baseline;
- `thinking-orbs@^0.3.1` preservation.

## CI gate

The intended final PR gate remains:

1. Node dependency install;
2. Composer install;
3. cumulative source contracts;
4. Coolify Compose validation;
5. PostgreSQL 17 + pgvector `migrate:fresh`;
6. client + SSR build;
7. TypeScript check after Wayfinder generation;
8. Pest application suite;
9. production Docker image build exactly like Coolify.

The release is not considered closed until the current PR HEAD passes the applicable GitHub Actions gates.
