# M13.5 — Durable Conversational & Operational Memory

M13.5 separates Tower's audit transcript from a durable memory layer. Tower can now remember stable decisions, preferences, goals, constraints, reusable context and completed mission outcomes across chat threads without resending the complete conversation history to the AI provider.

## Memory architecture

```text
Tower Chat
   │
   ├── recent raw messages (bounded)
   ├── rolling thread summary
   ├── relevant durable memories
   └── live Tower context
          ├── Observatory insights
          ├── pending approvals
          └── recent missions
             │
             ▼
        Chat Router
```

Durable memories are stored in `tower_memories`. They are versioned by semantic key: a changed value supersedes the previous active row instead of silently overwriting history.

Categories:

- preference
- decision
- goal
- constraint
- result
- context

Scopes:

- `academy`: reusable across Tower conversations in the current Academy instance;
- `thread`: temporary context restricted to one chat thread.

## Capture

The existing Tower Chat routing call now returns optional `memory_candidates`, so durable extraction does not require an additional AI call for every user turn.

Completed missions are also promoted deterministically to `result` memories linked to the mission/run/chat message. Failed and cancelled runs are not promoted as durable outcomes.

## Retrieval

Tower injects at most `TOWER_MEMORY_MAX_CONTEXT` memories per turn. Selection uses:

1. pinned memories;
2. pgvector cosine similarity when the existing Academy embedding provider is configured;
3. deterministic lexical + importance + recency fallback.

No new datastore or container is introduced.

## Rolling summary

Long threads no longer require an ever-growing provider context. Older messages are compressed into `tower_chat_threads.summary`, while the recent window remains verbatim. Original messages are never deleted; summary is only a context optimization.

## Memory Center

`/tower/memory` provides an inspectable control surface. The owner can filter memories, pin/unpin active memories and mark a memory forgotten. Forgetting memory does not rewrite Chat or Evidence history.

## Safety

Memory promotion rejects secret-like material and the extraction prompt forbids provider keys, MCP tokens, Stripe secrets, approval requestState and raw student PII. Memory never authorizes actions and never replaces MCP/Observatory for current Academy facts.

## Configuration

```env
TOWER_MEMORY_ENABLED=true
TOWER_MEMORY_MAX_CONTEXT=8
TOWER_MEMORY_SEMANTIC=true
TOWER_MEMORY_RETENTION_DAYS=365
TOWER_MEMORY_THREAD_RETENTION_DAYS=30
TOWER_CHAT_HISTORY_MESSAGES=8
TOWER_CHAT_SUMMARY_TRIGGER_MESSAGES=16
TOWER_CHAT_SUMMARY_BATCH_MESSAGES=16
TOWER_CHAT_MAX_SUMMARY_LENGTH=6000
```

## Real CI / Coolify gate

M13.5 hardens the repository workflows so the remote CI does not depend on the stripped release environment used to build this ZIP. GitHub Actions now provisions PostgreSQL 17 with pgvector plus Redis, runs migrations, M07→M13.5 contracts, client+SSR build, TypeScript and Pest. A separate `coolify-image` job validates `docker-compose.coolify.yml` and builds the exact production Dockerfile used by Coolify. The local release gate remains honest when Composer/vendor or native frontend bindings are unavailable.
