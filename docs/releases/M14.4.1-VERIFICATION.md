## Verification policy

M14.4.1 is release-ready only after the cumulative dependency-independent gate succeeds on the frozen source, on a fresh extraction of a control archive, and again on the exact final ZIP. Runtime probes that cannot execute in this artifact environment remain explicitly BLOCKED rather than being reported as PASS.

## TDD evidence

The new standalone contract was first observed RED on the v1.5.1 baseline because `AcademyFactoryBlueprintBuilder` did not propagate `TOWER_ENABLED` with the Tower capability.

A deeper runtime inspection then established that `AcademyMcpHttpGateway` also requires `TOWER_ACADEMY_MCP_TOKEN` to resolve to a real, active `AcademyMcpToken` database record even when `TOWER_ACADEMY_MCP_IN_PROCESS=true`. The milestone therefore tests and implements both layers:

```text
Factory Tower capability
→ runtime TOWER_ENABLED
→ generated Tower MCP secret
→ academy:bootstrap-instance
→ bounded database MCP identity
```

A Laravel feature test is included for the token provisioner (idempotency, rotation and exclusion of SENSITIVE tools), but execution of Pest is blocked locally by missing Composer dependencies.
