# M13.1 — Mission Tower Operations

M13.1 turns the M13.0 Tower foundation into a real human control plane while keeping Mission Tower isolated in `app/MissionTower` and `resources/js/mission-tower`.

## Surfaces

- `/tower` — overview/readiness plus recent missions/evidence.
- `/tower/missions` — build explicit MCP execution plans.
- `/tower/missions/{id}` — mission plan, attempts, approvals and evidence.
- `/tower/approvals` — human approval center.
- `/tower/runs` — immutable execution attempts.
- `/tower/evidence` — receipts and governance evidence.

## Runtime model

A mission contains ordered MCP tool steps. `MissionRunner` executes one step at a time through `AcademyGateway`.

1. READ tools execute and record an Academy MCP receipt.
2. WRITE/SENSITIVE tools return MCP `input_required`.
3. Tower stores the encrypted `requestState`, requested schema, receipt id and expiration in `tower_approvals`.
4. The human approves/rejects from the Tower UI.
5. SENSITIVE approvals require the exact phrase supplied by Academy MCP.
6. Approval retries the exact tool + arguments + `requestState` using MCP `inputResponses`.
7. A successful result is recorded in Evidence, then the same run continues to its next pending step.

Tower therefore does not bypass M08 governance and does not implement a competing authorization protocol.

## Persistence

- `tower_missions`
- `tower_mission_steps`
- `tower_runs`
- `tower_approvals`
- `tower_evidence`

`request_state` is stored with Laravel's encrypted cast. Evidence stores the upstream Academy MCP `receipt_id` whenever one is available.

## Access boundary

Trainers see their own Tower missions. Academy admins/super-admins can inspect all missions in the isolated Academy instance. Mission creation only accepts tools currently visible to the dedicated Tower MCP token, and Tower derives tool risk from the MCP metadata rather than trusting the browser.

## Current execution scope

M13.1 intentionally uses explicit tool plans. Natural-language mission compilation is a later M13 slice and will target this same persisted mission/step format.

NümFlow and Harness bridges remain optional/disabled. The local runner gives a working governed loop now; later NümFlow can own durable pause/resume/recovery while Harness can receive stronger evidence/approval policies without changing Academy MCP.
