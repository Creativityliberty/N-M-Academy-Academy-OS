# M07 — Academy AI v1

Release: **NÜM Academy OS v0.7.1**

M07 adds the first creator-facing intelligence layer while preserving the existing Laravel/React academy core and Coolify topology.

## Creator capabilities

Academy AI exposes six named capabilities:

```text
academy.ask
course.generate
curriculum.generate
lessons.generate
lesson.rewrite
students.analyze
```

The visible workspace keeps this simpler for the creator:

```text
Ask
Create
Modify
Analyze
```

`Create` contains full-course, curriculum and lesson generation.

## Propose → Apply

AI-generated writes never mutate academy data silently.

```text
Creator prompt
    ↓
AcademyAiRunner
    ↓
Capability Registry
    ↓
AiProvider
    ↓
academy_ai_runs
    ↓
Proposal shown to creator
    ↓ explicit Apply
Domain mutation
```

Read-only capabilities (`academy.ask`, `students.analyze`) never expose an Apply action.

Write capabilities create or modify data only after an explicit trainer action. Runs are owner-scoped and can be applied only once.

## Course generation

`course.generate` returns a structured blueprint containing:

- title and description;
- target audience;
- suggested price;
- benefits;
- objectives;
- prerequisites;
- total duration;
- modules;
- lessons;
- lesson content.

Applying the proposal creates a **draft** course. Stripe is intentionally not called during AI generation/application. When the trainer later publishes the course, the existing publishing path provisions missing Stripe Product/Price identifiers.

## Lesson content

M07 makes lesson text a first-class field with `lessons.content`.

The field is:

- generated by Academy AI;
- editable in the trainer Course Builder;
- rewritable through `lesson.rewrite`;
- displayed in the Student Course Player;
- server-side redacted for locked paid lessons.

M07 also hardens the public course page so paid lesson media URLs and generated lesson content are not serialized to unauthorised visitors.

## Provider isolation

Domain capabilities depend only on `AiProvider`:

```text
AcademyAiCapability
        ↓
AiProvider
        ├── OpenAiResponsesProvider
        ├── DeepSeekResponsesProvider
        └── DisabledAiProvider
```

M07.1 supports both OpenAI and DeepSeek through Laravel's existing HTTP client. Both adapters use a Responses-style API and structured JSON Schema output; no vendor SDK is added.

Provider selection:

```env
ACADEMY_AI_PROVIDER=openai # openai | deepseek | disabled
ACADEMY_AI_TIMEOUT=90

# OpenAI
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5.6-terra
OPENAI_BASE_URL=https://api.openai.com/v1

# DeepSeek
DEEPSEEK_API_KEY=
DEEPSEEK_MODEL=deepseek-v4-pro
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_REASONING_EFFORT=high # none | low | high | max
```

`ACADEMY_AI_MODEL` and `ACADEMY_AI_BASE_URL` remain optional cross-provider overrides. Provider-specific defaults are kept separate so selecting DeepSeek never accidentally reuses an OpenAI model name.

If no key is configured for the selected provider, Academy AI remains visible but its execution button is disabled and the backend has an explicit disabled provider.

## MCP-ready capability registry

Each capability already exposes:

- stable name;
- label;
- mode;
- risk level;
- whether Apply is permitted.

This is deliberately the contract M08 can expose as MCP tools without rewriting the business actions.

```text
academy.ask          read_only
course.generate      draft_write
curriculum.generate  draft_write
lessons.generate     draft_write
lesson.rewrite       write
students.analyze     read_only
```

## Privacy

Academy and student analysis context is aggregated before it reaches the provider. Student names and emails are not included in the AI analysis payload.

## Infrastructure

M07 adds no service to Coolify.

```text
Coolify Project
├── App
│   ├── Laravel / Inertia / React
│   ├── Academy AI
│   ├── Queue workers
│   └── Scheduler
├── PostgreSQL
├── Redis
└── Persistent storage
```

The only provider-specific deployment requirement is an environment secret such as `OPENAI_API_KEY` or `DEEPSEEK_API_KEY`.
