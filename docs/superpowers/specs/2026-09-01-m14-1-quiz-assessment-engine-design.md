# M14.1 Quiz & Assessment Engine Design

## Goal

Add durable, authored, auto-gradable quizzes and assessments to NÜM Academy OS without replacing the existing Course → Module → Lesson domain or the M09 Tutor quiz sessions.

## Architectural boundary

M14.1 introduces **authored learning assessments**. They are different from `TutorQuizSession`, which remains an ephemeral AI study aid for a single student.

- `CourseAssessment` = trainer-authored learning primitive stored with the course.
- `TutorQuizSession` = student-specific revision session generated by Tutor/RAG.
- M14.1 does not change completion/certificate rules. M14.3 will decide whether an assessment is required for course completion.
- M14.1 does not introduce `LessonBlock`.

## Data model

### CourseAssessment

Required `course_id`; optional `module_id` and `lesson_id` locate it pedagogically.

Fields:
- `title`, `description`
- `kind`: `quiz` or `assessment`
- `passing_score_percent` (0–100, default 70)
- `max_attempts` nullable (`null` = unlimited)
- `shuffle_questions`, `shuffle_options`
- `show_explanations`
- `is_enabled`
- `position`
- timestamps

Ownership is derived from `course.trainer_id`; no duplicate trainer id is stored.

### CourseAssessmentQuestion

Fields:
- `assessment_id`
- `type`: `single_choice`, `multiple_choice`, `true_false`
- `prompt`
- `explanation` nullable
- `points` integer >= 1
- `position`

M14.1 intentionally excludes free-text grading; assignments/open response belong to M14.2.

### CourseAssessmentOption

Fields:
- `question_id`
- `text`
- `is_correct`
- `position`

Validation invariants:
- single choice: exactly one correct option
- multiple choice: one or more correct options
- true/false: exactly two options, one correct

### CourseAssessmentAttempt

Fields:
- `assessment_id`, `user_id`, `attempt_number`
- `score_points`, `max_points`, `score_percent`
- `passed`
- `started_at`, `completed_at`

Only enrolled students with sufficient `CourseOffer.access_rank → Enrollment.access_rank → Module.minimum_access_rank` may attempt module/lesson assessments.

### CourseAssessmentAnswer

Fields:
- `attempt_id`, `question_id`
- `selected_option_ids` JSON
- `is_correct`
- `awarded_points`
- `feedback` nullable

Question explanation is returned after submission only when `show_explanations` is true.

## Scoring

`AssessmentScoringService` is the single scoring boundary.

- single choice: exact correct option = full points
- multiple choice: selected set must exactly equal correct set = full points; otherwise 0
- true/false: same rule as single choice
- no negative marking
- percent = rounded `(score_points / max_points) * 100`
- passed = percent >= `passing_score_percent`
- attempt number is allocated transactionally to prevent duplicate attempt numbers
- `max_attempts` is enforced server-side

## Trainer UX

New course-local workspace:

`/trainer/courses/{course}/assessments`

Capabilities:
- list authored assessments grouped by course/module/lesson target
- create/edit/delete/enable-disable
- add/edit/delete/reorder questions
- add/edit/delete/reorder options
- configure pass score, attempts, shuffling, explanations
- preview question count and total points
- “Generate with AI” creates an Academy AI proposal, never an immediate mutation
- Apply materializes the generated assessment; proposal semantics remain M07-compliant

The normal Course edit screen gains a small “Quiz & évaluations” entry point; its structure is not rewritten.

## Student UX

Course player receives lightweight assessment references. An assessment opens in a dedicated route:

`/student/courses/{course}/assessments/{assessment}`

Student experience:
- show title, description, question count, passing score, remaining attempts
- begin/submit attempt
- show score, pass/fail, per-question correctness and optional explanations after submission
- hide correct answers before submit
- inaccessible assessments return 403/404 according to authorization context

Assessment results do not yet alter `LessonProgress`; that is M14.3.

## Academy AI

New capability: `assessment.generate`.

Inputs:
- `course_id` required
- `module_id` optional
- `lesson_id` optional
- prompt/instruction
- optional `kind`, target question count and passing score

Structured output:
- title, description, kind, passing score
- questions with type, prompt, explanation, points and options with `is_correct`

AI output is validated before apply. Apply creates an enabled authored assessment owned by the trainer’s course.

## One-Brief-to-Course

Add optional `generate_assessments` option. New `assessments` step runs after materialization and before visual generation.

To preserve resumability and latency behavior, it generates **one module assessment per `advance()` call**, like narration generation. Provider failure makes this optional step `skipped`, not the whole course run failed.

State stores:
- eligible module count
- generated assessment count
- generated assessment ids

Review summary shows assessment count and exposes a link to the trainer assessment workspace.

## MCP / Tower

Add creator tools:
- `assessments.list`
- `assessments.get`
- `assessments.create`
- `assessments.update`
- `assessments.delete`
- `assessment.questions.create`
- `assessment.questions.update`
- `assessment.questions.delete`
- `assessment.questions.reorder`

All mutations are WRITE. No assessment tool is SENSITIVE in M14.1 because it cannot publish the course, charge money, or bypass enrollment.

Tower continues to use the MCP bridge; no direct `CourseAssessment` access is added inside Mission Tower.

## Review / publish integration

M13.9 Review Center gains an “Assessments” section showing authored assessment count and edit links. Pending Academy AI assessment proposals remain governed by the existing Academy AI proposal/apply lifecycle.

Course publication is **not blocked solely because a course has no assessment** in M14.1. Required assessment completion belongs to M14.3.

## Security

- Trainer mutations require course ownership/policy authorization.
- Student view/attempt requires enrollment and access-rank authorization.
- Correct options are never serialized to the pre-submit student payload.
- Attempt limits and scoring are server-side only.
- AI generation sends course/module/lesson educational content but no student PII.
- Existing M09 Tutor quizzes remain isolated and unchanged.

## Testing

TDD contract plus Laravel feature tests cover:
- authored assessment CRUD and ownership
- question validation invariants
- enrollment/access rank authorization
- correct scoring for all supported question types
- attempt limit enforcement
- explanations only after submission
- AI proposal before apply and materialization on apply
- One-Brief one-module-per-advance generation
- MCP tool registry/execution and risk classes
- Tutor quiz regression remains unchanged
- M07→M14.1 cumulative source contracts

## Version/release

Release target: **v1.3.0 — M14.1 Quiz & Assessment Engine**.

Cumulative ZIP policy remains unchanged: no `vendor`, `node_modules`, fonts, real `.env` or secrets; SHA-256; fresh extraction retest; runtime blockers must remain explicit.
